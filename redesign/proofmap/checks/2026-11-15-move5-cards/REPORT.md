## 1. 관문 결과

표기: **확인** = 파일·도구 출력·완료 알림으로 확인한 것. **추론** = 확인한 것에서 끌어낸 것. **추측** = 근거가 약한 예상. 토큰은 완료 알림의 `subagent_tokens`(다시 잴 수 없는 값이다).

| # | 판정 | 값 |
|---|---|---|
| G1 | 기준은 지남. 추측과는 크게 다름 | CON+DC를 한 차례에 연 subagent: 71,477 토큰(vertex당 35,739), 도구 사용 1(보고). 작성 세션 쪽: 지시문 쓰기 +12,156(측정; G3 지시문 약 0.3k 포함) + 묶음 일부를 읽어 둔 것 약 4k(추정) + 답 받기 약 14k(답 약 35k자에서 추정) ≈ 30k, vertex당 약 15k. 합 vertex당 약 51k로 기준 68k 아래다. 답 받기를 그 사이 문맥 증가 전부(40,172)로 잡는 가장 나쁜 경우 vertex당 약 64k다. 절감은 약 25%(최악 6%)다. 추측 25–30k와는 크게 다르다. 앞 측정에서 도구를 쓰는 agent가 둘을 묶어 연 값이 vertex당 43,820(작성 세션 쪽 비용은 지시 한 줄)이었으므로, **한 차례 호출이 묶기 위에 더 줄였다는 근거는 없다**. 줄인 것은 묶기다. 답은 손으로 옮기지 않았다(subagent 기록에서 스크립트로 꺼냄) |
| G2 | 기준은 지남 (n=1, 검토자 하나) | Sonnet(작성에 관여하지 않음) 하나가 CON 하나를 눈가림으로 원문 108–140과 대조: 새 방식(B = G1의 CON) 어긋남 0, 놓친 의존 0, 표시 없는 덧붙임 0. 지금 방식(A = `B-ga-CON`) 어긋남 0, 놓친 의존 0, 표시 없는 덧붙임 2(`|B_i|\le1` 쓰기, Cauchy–Schwarz의 명시적 꼴; 둘 다 수학적으로 옳고 표시만 없음). 기준 합 0 ≤ 0. 검토자는 두 판 모두 기호 표 밖의 정의(`v_N`, `mu`)를 node 안에 적지 않은 점을 "엄격히 읽으면 둘 다 해당"으로 적었다. **말할 수 있는 것은 "새 방식이 나쁘지 않았다"까지다** (`G2-result.json`, `G2-key.json`) |

**G3 뒤의 상태.** 앞 보고서의 "S × 차례 수"는 틀렸다. 차례를 하나 늘려도 약 5k만 늘었다. **고정분 약 60k의 원인은 모른다.** 측정에서 보이는 설명 후보는 추측으로만 적는다: (추측) `subagent_tokens` 가 차례마다 다시 센 합이 아니라 마지막 문맥의 크기에 가깝고, 고정분의 대부분은 agent 종류마다 다른 시스템 문맥(도구 정의 포함)이다. 그렇게 보면 general-purpose 약 55–65k, Explore 약 35–48k가 되고 두 Explore 점은 서로 잘 맞지 않는다. 생각(thinking) 토큰이 이 값에 들어가는지 모른다. 이 후보는 B의 결과(Explore가 적고, 묶으면 vertex당 줄어듦)와 어긋나지 않지만 그것을 확인한 것은 아니다. 결정에 쓰는 것은 G1·B의 실측뿐이다. 앞 보고서 5절 제안 1의 근거 문장("차례가 빠져서 준다")은 근거를 잃었다.

**관문 판정 요약.** G1·G2는 미리 적은 기준을 지났다. G3은 미리 적은 규칙대로 추론을 기각했다(진행을 막는 관문이 아니라고 미리 적었다). "관문 셋을 통과"라고 쓰지 않는다.

**하네스 비용과 파이프라인 비용.** 작성 세션 쪽 약 15k/vertex 가운데 지시문을 손으로 쓰는 몫(약 6k/vertex)과 묶음을 미리 읽어 두는 몫은 이 하네스가 Agent 도구에 글로만 입력을 넘길 수 있어서 생긴다. 스크립트가 묶음을 만들어 바로 넘기는 파이프라인이면 없어진다(추측). 판정은 실제로 든 합으로 했다.

산출 검사(확인): G1-CON, G1-DC, G3-CON을 `move5.v2` 사본에 넣어 `check()` → 셋 다 그 graph 안에서 오류 0, 경고 0(통합 때와 같은 기계 보정 16/18/36곳).

## 3. P2 — 카드 뼈대

**방법(확인).** `card_skeleton.py` 가 카드의 `children`(잎)·원문 줄·`uses` 로 뼈대를 기계로 만든다(카드는 읽기만). 대응표 일부(외부 정리 8줄, 기호 9줄)는 작성자가 손으로 적었다. LLM(Explore 한 번, 도구 쓰지 않음)은 뼈대 edge의 쓰인 줄, 카드에 없는 의존, 원문에 없는 걸음, 카드·원문 어긋남만 채웠다(`P2-fill.json`). `assemble_cards.py` 가 원문 참조 판(SPEC 7.8) 하위 graph로 조립한다. 외부 입력의 항목 이름은 카드가 정하지 않아 작성자 표(8줄)로 정했다. IDE는 카드가 한 장(자식 없음)이고 증명이 없어 열지 않았다.
