# 첫 변분의 context 제거 PoC

2026-11-14. **fv와 cp에서 전제 전달을 실제 입력 edge로 통일했다.** 등록된 장치를 통해 자식이 부모에게 없는 전제를 추가하는 경우를 검출하는 국소 통과 기준을 충족했다. 자연어 전체의 수학적 함의를 자동 검증한 결과는 아니다.

## 바뀐 의미 구조

- fv.FF, cp.CF 및 각 node의 local_context를 제거했다. 두 graph에 `premise_mode: edges_only`를 지정했다.
- top.O1의 이름 붙은 입력 `fv_inputs`에 setting, insertion, terminal, recursion, kernel, bounds, path_mean을 선언했다. diff-e9는 이를 참조한다. 가정·정의·원문에서 인용한 단조성 사실을 독립된 파생 결론으로 오인하지 않도록 `role: given`으로 구별한다.
- fv의 기존 외부 입력 네 개는 부모 diff-e9의 정확한 항목을 선택한다. 같은 XO를 가리킨다는 집합 검사만으로 통과하지 않는다.
- 공통 가정·기호를 공급하는 XSET와 g1/g2/g3를 추가했다. CP의 실제 입력에도 XSET가 나타난다. cp는 새 외부 입력 XS를 통해 그 부모 g3가 공급하는 항목을 받으며 p0/p1/p2로 필요한 계산에 전달한다.
- c는 별도 전제로 두지 않고 norm/a로 풀었다. 미분 약어와 임의의 d/r은 로컬 도입으로 명시한다. 도함수 경계는 계속 TM/PM의 유도 결과다.
- 외부 입력 항목 선택은 원문 항목을 그대로 가져온다. FP_BIND의 대입처럼 실제 변환을 항목 선택으로 숨기지 않는다.

| graph | 전 | 후 | 변화 |
|---|---|---|---|
| fv | node 8, edge 10, context 1 | node 9, edge 13, context 0 | 공유 외부 입력 1개, 실제 edge 3개 추가 |
| cp | node 7, edge 7, context 1 | node 8, edge 10, context 0 | 부모 설정을 받는 외부 입력 1개, 실제 edge 3개 추가 |

안쪽 계산 node 수는 각각 3개로 유지했다. 전체 graph 수는 6개다. diff/p7/fresh의 기존 context는 이번 범위 밖이다. 기존 첫 변분 출력과 조건을 강화하지 않았으며 가정의 공급 통로를 바꿨다.

## 전제와 기호의 출처

setting은 유한 L, kernel, 지수, root 및 prefix를 공급한다. insertion은 유계이고 매개변수와 무관한 D, A의 선형 형태, 양의 경계와 근방, 방향 지표를 공급한다. Y 재귀와 tilted kernel, 단조성, path 평균 정의는 별도 항목이다. 원문 근거는 trees.tex 20–23, 67–82, 107–110, 142–154다.

입력에 새 b 경계를 덧붙이거나 새로운 근방 축소를 몰래 수행하지 않았다. 이전에 부모 diff-e9가 이미 공급하던 조건을 분해해 참조한 것이다. 더 약한 원래 진술로 범위를 넓히는 문제는 별도의 추론으로 다뤄야 한다.

각 항목의 defines와 bindings가 수신처까지 따라간다. 같은 j라는 표기라도 다른 binding id를 공급하면 불일치다. 미분 기호의 로컬 약어는 입력의 j에 의존하고, PM의 d 및 JOIN의 r/d 등은 입력 L의 범위 안에서 도입한다. 출력에는 generalizes, 귀납 고리에는 index_scope를 기록한다. 이 도입은 사실을 추가하는 두 번째 전제 통로가 아니다.

이름 붙은 출력의 지문은 현재 선택된 실제 항목의 내용·binding도 포함한다. 원본 항목이나 projection·로컬 도입이 바뀌면 검토 기록이 낡는다. 작성자가 출처와 기존 TM/PM/CP 유도를 대조한 뒤 기준 자료의 검토 기록을 갱신했다. confirmed로 승격하거나 독립 검토를 받지는 않았다.

## 시험

새 `test_edge_only.py` **15개 통과**:

- context/local_context/독립 조건이 없고 유도에 context 참조도 없는 기준 상태.
- 외부 입력 항목이 실제 부모 입력의 부분집합임을 확인.
- 부모 입력에서 insertion 항목을 제외하거나 존재하지 않는 항목을 가져오면 오류·미완결.
- context 재삽입, local_context·conditions·로컬 가정 도입, 부모에게서 오지 않은 새 외부 가정 추가를 검출.
- 같은 표기의 다른 binding, 잘못된 로컬 scope, 닫지 않은 지표, 다른 귀납 지표를 검출.
- 공유 입력 edge 삭제 시 숨은 전역 공급으로 대체하지 않고 미정의 기호를 보고.
- 매개변수 독립성을 바꾸면 재검토 상태로 돌아감.

기존 명시 참조 21개, 보기 11개, 출력 계약 12개, 검토 순환 4개, 문맥 건넘 7개, 수치 검산 5개도 통과했다. **Python 시험 합계 75개.** 기존 검토 순환 시험은 이름 붙은 중간 출력과 모든 수신 기록까지 재검토하도록 범위를 넓혔다. 정의 삭제 시험도 이제 사본이 아닌 canonical 항목의 정의를 삭제한다.

구조 검사 오류 0·경고 0. Node 경로 회귀 시험 및 생성 JavaScript 문법 검사 통과. 공유 입력선에 필요한 좌우 우회 후보도 추가해, 기존 c1 사례와 새 공유 입력 경로를 함께 검사했다. JSON Schema는 선택적 항목을 문서화했으며 별도 jsonschema 엔진 적용은 환경에 패키지가 없어 수행하지 않았다.

브라우저에서 fv의 틀 0개, edge 전용 표시, 공유 입력의 부모 diff-e9 항목 추적, PM의 입력 6개와 별도의 로컬 기호·지표 도입을 확인했다. `fv-edge-only.png`, `pm-introductions.png`가 화면 기록이다.

## 한계와 다음 판단

이 검사는 등록된 전제·projection·binding·범위의 일관성을 검사한다. 자연어 by 안의 임의 주장, 잘못된 defines 목록, 지표 일반화의 실제 수학적 타당성까지 판단하지는 않는다. 바닥으로 선언한 미적분과 적분 규칙도 그대로 남는다.

다음 판단 대상은 이 표현이 실제로 더 읽기 쉬운지, 같은 원칙을 나머지 graph에 적용할지다. 이번에 다른 graph까지 자동 변환하지 않았다. 변환 전 해당 graph 자료는 before.json, 기준 검사와 전제 대응은 check-results.json 및 import-map.json에 저장했다.
