## 1. 한 줄 요약

수학 논문의 증명을 **증명 지도**(node, edge, 문맥으로 된 graph이고 node를 열면 더 미시적인 graph가 나오는 것)로 다시 짓는다. 지금은 논문의 일곱 수 가운데 수 4 하나를 여섯 장의 graph로 옮겼고, 첫 변분 `fv`와 그 하위 `cp`, fresh path `fresh`의 안쪽 vertex를 국소 완결했다. 상위 graph 전체는 미완결이다. 다섯 PoC의 첫 실행을 마쳤으며, PoC 5는 상위 1층까지 수정이 번진 결과다.

## 5. 정해진 것

**[확정]**
- 가독성은 읽는 사람의 심리가 아니라 로직 연결의 단순함·효율성·활용성으로 정의한다.
- 출력은 증명 지도다. node를 확대해 미시적인 지도로 들어가고, 맨 아래가 모두 증명된 내용이면 위도 믿을 수 있다. 연결하는 산문 없이 지도만으로 읽히는 것을 노린다.
- 완결의 단위는 node가 아니라 **vertex**(받는 edge + node + 보내는 edge)다.
- edge는 내용을 스스로 갖는다. edge는 보낸 node의 출력 가운데 일부만 싣고, 열면 싣는 내용 전체가 나온다.
- vertex 둘레에서, 받는 edge와 문맥만으로 node의 유도로부터 보내는 edge 전부가 나와야 한다. 국소적으로 완결이어야 검증하기 편하다.
- node 안의 유도가 여러 걸음이면 그 안은 다시 graph여야 하고, 안이 모두 완결되기 전에는 바깥도 완결이 아니다.
- 평가는 최종 글만이 아니라 구조를 본다. 사용자가 구조를 직접 본다.
- 처음부터 전부 짓지 않고, 과제에 맞는 기존 library를 검색해 rule 단위로 들인다. 하네스 안에서는 용어집에 담은 재료만 쓴다.
- 큰 프로젝트로 한 번에 하지 않고 작은 PoC로 나눠 간다.
- 작업 자료는 여러 서비스·모델·세션이 오갈 수 있게 로컬에 두고, graph 자료형은 널리 쓰이는 형식으로 한다(이 폴더가 그 결과다).

**[제안]** (설계문서에 있고 사용자 판정 전)
- node의 종류 여섯, edge의 종류 셋, 문맥의 표기.
- 원자 node의 기준과 바닥(독자의 바닥, 원문의 바닥)의 선언.
- 국소적으로 키우는 연산 다섯과 전체 검사 셋(순환, 문맥을 건너는 edge, 기호의 뜻).
- 한 장의 안쪽 node는 아홉 개 안팎.

**바꾸지 않는 것** (프로젝트 전체의 제약)
- 세부는 잃어도 참은 잃지 않는다. 증명보다 많이 말하면 차이를 적는다.
- 논문이 증명하지 않는 동일시(RPC, Ghirlanda–Guerra, ultrametricity, pure state)는 이름으로 쓰지 않는다.
- 섭동 매개변수 $\mathbf u$ 는 고정값이다. 보조 계층의 깊이 $L$ 을 RSB 단수로 읽지 않는다. 하한은 $\liminf$ 꼴로만 닫힌다.
- `confirmed` 는 사용자만 붙인다. 독립 검토는 작성자와 다른 모델이 한다.

## 6. 사용자의 판정을 기다리는 것

1. `PM` vertex가 원한 완결의 꼴인가. 식 여섯 줄을 "계산 하나"로 본 것이 맞는가.
2. `PM` 의 식 2에서 작성 모델이 채운 정당화가 맞는가.
3. 바닥에 둔 것(연쇄 법칙, 적분 기호 아래의 미분)을 edge로 올려야 하는가.
4. 정의를 문맥에 둘지 edge로 둘지. 원자 수준에서는 정의가 거의 모든 node로 들어가 edge 수가 불어난다.
5. 설계문서 9절의 제안들.
6. 현행 L2의 산문을 없앨지, 지도에서 만드는 부산물로 둘지.

## 7. 다음에 할 일

작은 PoC 다섯 개. 권하는 순서대로다. 하나가 하나의 질문에 답하고, 돌리기 전에 통과 기준을 적고, 실패하면 기록만 한다.

| | PoC | 답하는 질문 | 통과 기준 |
|---|---|---|---|
| 1 (완료) | `fv` graph 닫기 | 맨 아래부터 완결해 node 하나를 끝까지 확인할 수 있나 | `TM`, `CP` 완결. `fv` 대강 0·열림 0, 하위 `cp`도 안쪽 전부 완결. 구조 검사 오류·경고 0 |
| 2 (국소 시험 통과) | 독립 검증 | 완결된 vertex는 그것만 보고 검증할 수 있나 | PM 전체 입력: 6줄·출력 확인. e2 삭제 입력: 누락 정의와 출력별 영향을 탐지. 신규 독립 agent, 각 조건 n=1 |
| 3 (국소 시험 통과) | 기계 검사 넓히기 | 손으로 채운 검사표를 기계로 바꿀 수 있나 | 원자 vertex 5개의 명시 기호 정의 위치·입력 사용 보고. 결함 주입 시험 21개 통과. 선언에서 빠진 기호의 자동 추출은 범위 밖 |
| 4 (국소 시험 통과) | 문맥 건넘 | edge가 균일성과 극한 순서를 실을 수 있나 | `top-e9`에 고정 L 유한 최대 오차와 N→∞ 후 L→∞를 명시. 합성 반례 등 7개 시험 통과. 받는 쪽 전체 증명은 미완결 |
| 5 (실행 완료: 상위 1층 수정) | 대강에서 키우기 | 국소적으로 고치는 일이 둘레 안에서 끝나나 | D4 국소 완결. 새 edge 11개, 기존 edge 4개 보충. 정의 입력 부족으로 상위 1층에 전파. 완전히 둘레 안에서 끝나지는 않음 |

그 뒤의 갈래(설계 메모 5절, 7절): library 대조표(미분 규칙의 최소 가정과 대응 카드), 닫힘 완성으로 표현 찾기, 다음 단계 예측 시험, 수 5–6에서 문맥이 수렴 양식을 담는지.

4절의 알려진 어긋남도 할 일이다. 수 4를 닫으려면 그다음은 `top` 의 R2·R3·F1·F2와 `p7` 의 T0–T5를 하위 graph로 여는 일이다(p7은 T2, T5, T3 순서를 권한다).

## 8. 작업 규칙

- 자료는 `graphs/*.json` 만 고친다. 고친 뒤 `check.py` 를 돌리고 보기를 다시 만든다.
- 원문 줄 범위와 대조하지 않은 진술을 넣지 않는다. 원문에 없는 걸음은 `author_filled` 로 표시한다.
- 모르는 것은 `sketch` 나 `open` 으로 적는다. 완결이 아닌 것을 완결이라고 적지 않는다.
- 카드, `rules.md`, L2, 용어집은 이 갈래에서 고치지 않는다. 고칠 것이 보이면 이 문서 4절에 적는다.
- 사용자에게는 한국어 평서문으로, 확인한 것과 추론과 추측을 갈라 보고한다. 저장소 파일을 읽었으면 경로를 댄다.
- 사용자는 실험보다 논의를 먼저 원하는 때가 있다. 큰 작업을 시작하기 전에 방향을 묻는다.
- 커밋과 push는 사용자가 요청할 때만 한다. 2026-11-14 현재 이 폴더와 `notes/` 의 새 파일들은 커밋되지 않았다. 브랜치는 `ccr-b259047e-6p25yb` 다.
