## 남은 경고 4건과 이유 (모두 c, 카드 변경 없음)

1. `decor:conditional-concentration.s3.s1`, `decor:overlap-concentration.s2.s1` ← `x:pert-colored-extensions`. 이 카드의 `provides` 는 "decor:overlap-concentration.s1, s2.s1, decor:conditional-concentration.s2.s1, s3.s1" 처럼 **줄임 표기**(앞 ID 뒤에 `s2.s1`)로 두 카드를 이미 가리킨다. 사용도 실제로 있다. 검사는 완전한 ID 토큰만 읽으므로 줄임 표기를 못 읽는다.
2. `x:pert-standing` ← `cavity:increment`, `x:cavity-tree-sampling`. 두 카드의 `provides` 는 "pert:section (perturbations.tex 3–8 / 6 ...)" 로 §6 섹션 카드를 이름으로 적고, 인용한 줄이 `x:pert-standing`(perturbations.tex 4–10) 안이다. 그런데 `x:pert-standing` 은 `pert:section` 의 `children` 에 들어 있지 않은 약속 카드라서 검사의 가족 정의(`fam`)에 섹션 카드가 들지 않는다. 검사 자신의 소속 정의(`sec_of`)로는 같은 섹션인데도 맞물림을 못 알아본다.

## 검사 개선 제안 (제안만, `tools/check.py` 는 건드리지 않음)

1. **줄임 ID 해석.** `provides` 에서 완전한 ID 뒤에 오는 `, s2.s1`, `s3` 같은 꼴을 직전 ID 의 접두어에 붙여 읽는다(남은 경고 2건). 또는 `SCHEMA.md` 에 "`provides` 에는 완전한 ID만 쓴다"를 규약으로 적고 카드를 고친다.
2. **섹션 이름을 가리키는 `provides` 의 인정.** `fam(B)` 에, `B` 가 `sec_of` 로 속한 섹션 카드를 넣는다. `children` 에 안 든 약속 카드(`x:pert-standing` 등)가 섹션 카드의 이름만 적힌 `provides` 로 받아지는 경우를 구한다(남은 경고 2건).
3. **예시·비수신 언급 제외.** S1 21건 전부가 "받는 쪽이 아닌 것"을 적은 `provides` 였고 그중 다수는 문장이 스스로 "이 카드를 받아 쓰지 않는다 / 예 / 같은 꼴"이라고 말한다(`model:positivity의 예`, `이 진술을 받는 것은 아님`, `받아 써도 되고 안 써도 된다`). 이런 문장을 검사가 구별할 수는 없으므로 규약으로 풀 것을 제안한다: 받지 않는 대응은 `provides` 가 아니라 본문에 `[[id]]` 링크로 적고, `provides` 는 받아 쓰는 카드만 적는다(`SCHEMA.md` 의 예고 처리와 같은 방식). 그러면 이번 같은 b 건이 생기지 않는다.
4. **S2 의 상대 방향 구제.** S1 21건 가운데 반대 방향 사용이 이미 있는 것은 4건(`models:*` → `model:*`, `pert:factor`)이었다. S1 에서 "R 이 A 를 `uses` 로 가지지 않는데 A 가 R 을 `uses` 로 가지면" 메시지에 "반대 방향 사용이 있음, 예시 언급일 수 있음"을 덧붙이면 판정이 빨라진다.
5. **약한 근거의 구분.** a 로 분류한 건 중 `pert:factor` ← `cavity:factor-bounds`, `x:pert-mark-specification` ← `x:tree-path-kernels`·`x:tree-sampling` 은 원문에 `\ref` 가 없고 "틀·용어를 받는" 사용이다. 사용자가 `confirmed` 를 붙이기 전에 한 번 보면 좋다.
