## 2. 항목별 상세

### 대칭 검사 (`check.py`, 함수 `symmetry_warnings`)

정의(카드 형식을 읽고 정함):

- `provides` 는 자유 문장이다. 그 안에 적힌, 실재하는 카드 ID(맨 ID든 `[[id]]`든)를 "이 카드를 받아 쓰는 쪽"으로 읽는다. `x:overview-*` 는 예고를 표로 잇는 약속이라 양쪽에서 뺀다.
- 섹션은 `kind: section` 카드의 자손 관계로 정한다(`main:theorem` 은 두 섹션). 자손이 아닌 카드는 첫 `source` 파일을 덮는 섹션 카드에 속한 것으로 본다. 섹션 집합이 겹치면 같은 섹션이라 검사하지 않는다. 가족 fam(X) = X와 조상·자손.
- **S1** `A.provides` 가 다른 섹션의 카드 R 을 가리키는데 fam(R) 의 어느 카드도 `uses` 에 fam(A) 의 카드를 갖지 않는다.
- **S2** 카드 B 가 다른 섹션의 카드 A 를 `uses` 에 넣었는데 (a) `A.provides` 가 fam(B) 를 가리키지 않고, (b) A 의 섹션 카드(조상 포함)의 머리말·본문이 fam(B) 를 가리키지 않고, (c) B 의 섹션 카드(조상 포함)가 fam(A) 를 가리키지 않는다. (b)(c) 는 "섹션 카드의 밖에서 받는 것 / 내주는 것 표"의 기계적 근사다.
- 경고만 낸다. 종료 코드에 영향 없음. 카드가 없으면 "해당 없음".

현재 `cards/` 에서: **경고 48건**(S1 21, S2 27). 다른 검사는 모두 오류 0·경고 0. 예:

- S1: `x:tree-cancellation-example`.provides 가 `decor:conditional-concentration.s2.s1` 을 가리키지만 그쪽 `uses`(조상·자손 포함)에 없다.
- S1: `pert:factor`.provides 가 `cavity:factor-bounds` 를 가리키지만 `cavity:factor-bounds` 쪽에 `pert:factor` 가 없다.
- S1(오탐 가능): `models:sat`.provides 가 "`model:positivity` 의 예"라고 적어 받는 쪽처럼 읽혔다. 예시 언급이다.
- S2: `pert:factor`.uses 의 `cavity:factor-bounds` 를 `cavity:factor-bounds`.provides 도 양쪽 섹션 표도 가리키지 않는다.
- S2: `pert:palm-expression`.uses 의 `x:tree-extra-variables` 를 주는 쪽이 적지 않았다.
- S2 묶음: `x:pert-standing` 이 `cavity:grid`·`cavity:increment`·`x:cavity-bounded`·`x:cavity-tree-sampling` 을, `x:pert-increment` 가 `model:hamiltonian`·`cavity:increment` 등을 `uses` 에 넣었으나 주는 쪽 `provides` 에 없다.

경고는 §6(pert)가 §3(tree)·§5(cavity)를 받는 부분에 몰려 있다(S2 27건 중 26건이 `pert:`·`x:pert-` 카드). 카드 내용 문제이므로 고치지 않았다. 목록 전체는 `python3 tools/check.py --out /tmp/x.md` 의 "대칭" 절. 알려진 오탐: `provides` 가 받는 쪽이 아닌 카드를 "예"나 "근거"로 언급하면 S1이 걸린다.

### 포함 검사의 구멍(발견·수정)

fixture 시험 중, 증명이 진술과 다른 파일에 있는 정리(`main:theorem`: 진술 model.tex 130–136, 증명 reduction.tex 45–87)의 **증명 줄이 포함 검사 대상에서 빠져 있었다**(진술 파일에서만 증명 범위를 모았다). 그래서 `main:theorem.s1`–`s4` 를 지워도 포함 검사가 통과했다. `check.py` 에서 증명 범위를 진술 파일과 무관하게 모으도록 고쳤다. 실제 카드는 여전히 통과(오류 0).

### 두 부모와 지도 (`build.py`)

- **카드 수 중복: 없음.** `Struct` 가 `main:theorem` 과 그 자손을 "주정리" 묶음에만 센다. 섹션별 합 244 = 카드 244. 카드 쪽(`main.theorem.html`)은 "상위: model:section(§2), reduction:section(§9)" 를 둘 다 보이고 "섹션: 주정리"만 센다고 적는다. §2·§9 카드 쪽은 "주정리는 이 섹션 카드의 자식이지만 따로 센다"를 적는다. 이 둘은 이미 맞게 되어 있었다.
- **위로 링크:** 사이트에는 "위로" 링크가 없고 "상위:" 목록이다. 부모가 둘이어도 둘 다 나온다. 정상.
- **가짜 순환(고침).** 섹션 지도의 섹션 간선 28개로 §2, §4, 주정리, §3, §5, §6, §7, §8, §9 아홉 섹션이 한 강연결 성분이었고 "서로 쓰는 쌍" 4개(모형–주정리, 모형–상한 둘씩)가 있었다. 원인은 두 부모가 아니라 `remark` 카드: `x:model-theorem-scope`(주석, `main:theorem` 을 `uses`) 와 `x:model-moment-finiteness`(주석, `upper:bound.s1` 을 `uses`) 가 앞 섹션에서 뒤 결과를 가리켜 섹션 단위 뒷간선을 만든다. 카드 단위로는 순환이 없다. 고침: `remark` 카드와 `x:overview-*` 카드의 `uses` 는 **점선("주석 n")** 으로 따로 그리고 순환 판정에서 뺀다(`build.is_note_card`, `section_edges`). 결과: 실선 간선만으로 섹션 순환 0, 서로 쓰는 쌍 0. 지도 쪽에 이 규칙과 순환 성분 유무를 적는다. HANDOFF의 "overview는 논리적 의존으로 보이지 않게" 요구도 같이 충족.
- 섹션별 지도(`map-main.html` 등)의 안쪽 카드·밖 노드 구성은 바꾸지 않았다.

### 도구 개선 부산물

- `render_maps.py --out DIR`, `export_artifact.py --site/--out/--maps`: 실제 `build/artifact/` 를 건드리지 않고 임시 위치로 전 과정을 돌릴 수 있다.
- `render_maps.py` 의 tar 풀기에 `filter="data"`(Python 3.14 경고 제거).
- 좁은 화면: `build.py` 의 쪽마다 작은 스크립트가 줄바꿈 안 되는 긴 인라인 수식만 `mjx-container.wide`(블록, 안에서 스크롤)로 바꾼다. 아래 4절의 48쪽 넘침의 원인이었다. `mjx-assistive-mml{max-width:100%}` CSS도 추가(MathJax의 보조 MathML이 컨테이너보다 넓어 쪽을 밀던 것). 한 파일 내보내기는 이미 자체 `fit` 이 있었고 이 CSS만 공유한다.

완화 규칙별:

- **완화 1(진술 줄은 정리 카드가 덮어도 됨):** 통과 조건으로 시험. 진술 줄 누락은 여전히 오류. 증명 줄은 잎이 덮어야 한다는 것도 시험.
- **완화 2(뒤에 나오는 대상은 예고라 제외):** 직접 시험은 하지 않았다(본문 `role: text` 참조가 필요한데 fixture가 다루는 원문 범위에 마땅한 예가 없다). **시험하지 못한 곳**이다.
- **완화 3(섹션 라벨 참조는 자손이 `uses` 에 있으면 충족):** comparison.tex 227 이 대상. (a) 섹션 카드의 자손을 `uses` 에 넣으면 경고 없음, (b) 조상 카드의 `uses` 에 넣어도 충족, (c) 자손을 뺀 경우, (d) 그 섹션의 자손이 아닌 카드만 넣은 경우는 **여전히 경고**, (e) 이 완화는 섹션 라벨에만 적용되고 정리 라벨(upper:bound)에는 적용되지 않음(경고 유지). 즉 이 규칙이 기존 오류를 놓치지는 않는다.

## 4. 헤드리스 브라우저 검증 (수치)

도구: `tools/verify_site.py` / `.js`(Playwright 노드, Chromium은 기존 설치). 390px 폭. 대상: `build.py --out /tmp/m2p-site` 로 지은 사이트와 그것으로 `export_artifact.py` 를 돌려 만든 한 파일(`/tmp/m2p-artifact/`, 지도 SVG는 `/tmp/m2p-maps/` 에 새로 그림). 실제 `site/` 와 `build/artifact/` 는 쓰지 않았다.

검증 과정에서 나온 문제와 처리:

1. **고치기 전 사이트: 390px 가로 넘침 48쪽.** 줄바꿈 안 되는 긴 인라인 수식(예: `cards/comp.patterns.s2` 가 714px, `cards/cavity.increment.s1` 522px)과 MathJax 보조 MathML의 폭이 원인. 도구(`build.py`)의 문제라 고쳤다(2절). 한 파일 내보내기는 앞서 `fit` 이 있었으나 보조 MathML 때문에 1쪽(`cards-comp-patterns-s2`, 393px)이 남았고 CSS로 고쳤다.
2. 검증 스크립트 자체의 함정 둘(수치 왜곡의 원인이었음, 기록해 둔다): `typesetPromise()` 를 다시 부르면 보조 MathML이 중첩되어 수식 수가 두 배로 세어지고 가짜 넘침이 나온다. 웹 폰트가 오기 전에 재면 폭이 일시적으로 넘친다. 지금은 `startup.promise` + `document.fonts.ready` 뒤에 잰다.
3. MathJax 3.2 는 정의 안 된 매크로를 `mjx-merror` 가 아니라 **빨간 글씨 `mjx-mtext`** 로 그린다. `mjx-merror` 만 세면 놓치므로 둘 다 센다(`test_verify.py` 가 일부러 깨뜨린 사이트로 확인).
4. 카드 내용 문제로 보이는 것: **없음**(수식 오류 0, 깨진 링크 0).

한계: 화면의 모양(지도의 읽기 쉬움, 레이아웃의 미감)은 사람이 보지 않았다. 수치는 오류·넘침·링크만 말한다. 한 파일 내보내기의 Mermaid 는 미리 그린 SVG라 지도 렌더 오류는 `render_maps.py` 단계에서 보인다(12개 모두 성공).

## 5. SCHEMA 표에 넣을 제안 문구 (적용은 하지 않음)

"적법성 검사" 표의 의존 행 다음에 다음 행을 넣는 것을 제안한다.

> | 대칭 | (경고만) 카드 A 의 `provides` 가 다른 섹션의 카드 R 을 가리키면 R 쪽(R 과 그 조상·자손)의 `uses` 에 A(또는 그 조상·자손)가 있고, 카드 B 가 다른 섹션의 카드 A 를 `uses` 에 넣었으면 A 의 `provides` 나 양쪽 섹션 카드의 "밖에서 받는 것 / 내주는 것" 표가 B(또는 그 조상·자손)를 가리킨다. `x:overview-*` 는 제외 |

그리고 "카드" 절의 "`\ref` 없는 사용은 …" 줄 끝에 "이 세 곳의 맞물림은 `check.py` 의 대칭 검사가 경고로 알려 준다"를 덧붙일 수 있다. 또 의존 행에 "조상 카드의 `uses` 도 충족으로 본다"가 이미 반영되어 있는지 확인할 것(현재 문구는 "조상·자손의 `uses`" 로 맞다).

## 6. 바꾼 파일과 조율자의 최종 재생성 순서

바꾼 파일(모두 `redesign/` 아래):

- `tools/check.py` — 대칭 검사 추가, 포함 검사에서 다른 파일에 있는 증명 줄 요구
- `tools/build.py` — 섹션 지도의 주석 점선·순환 판정, 좁은 화면 수식 스크립트와 CSS
- `tools/render_maps.py` — `--out`, tar 필터
- `tools/export_artifact.py` — `--site`, `--out`, `--maps`
- `tools/verify_site.py`, `tools/verify_site.js` — 새 파일
- `tools/tests/fixture.py`, `test_check.py`, `test_build.py`, `test_verify.py` — 새 파일
- `tools/README.md` — 대칭 검사, 두 단계 지도, `render_maps`, `export_artifact`의 maps 읽는 법, 검증, 시험, 알려진 한계
- `build/tools-2026-11-12.md` — 이 파일

(`tools/render_maps.js`, `common.py`, `extract.py` 는 바꾸지 않았다. 도구를 고친 일부는 저장소의 스냅샷 훅이 이미 커밋했을 수 있다.)

조율자가 카드·층 작업이 끝난 뒤 돌릴 명령(redesign/ 에서; `extract.py` 는 원문이 안 바뀌었으므로 생략):

```
python3 -m unittest discover -s tools/tests          # 도구 시험(카드와 무관, 약 3초)
python3 tools/check.py                                # build/check-report.md (대칭 경고는 정보)
python3 tools/build.py                                # site/  (build.py 가 바뀌었으므로 반드시 다시)
python3 tools/render_maps.py                          # build/artifact/maps/ (지도 텍스트가 바뀌었으므로 반드시 다시)
python3 tools/export_artifact.py                      # build/artifact/mezard-parisi.html
python3 tools/verify_site.py --site site              # 사이트 검증
python3 tools/verify_site.py --artifact build/artifact/mezard-parisi.html   # 한 파일 검증
```

실제 `site/`, `build/artifact/`, `build/check-report.md` 는 이 작업 이전 상태 그대로라 낡았다(특히 지도 SVG는 점선 규칙 이전, `site/` 는 좁은 화면 수정 이전).
