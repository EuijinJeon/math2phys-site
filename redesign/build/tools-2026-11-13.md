# 도구 보강 검증 (2026-11-13)

## 범위와 결과

`HANDOFF.md` 1.2의 중단된 도구 작업을 독립 root `/tmp/m2p-site`로 검사했다. 이 보고의 카드 사본은 작업 도중의 244장 스냅샷이므로 최종 카드 변경 뒤 검사를 다시 실행해야 한다. 내용의 수학적 정확성은 이 검사로 판정하지 않는다.

- `check.py --root /tmp/m2p-site --out /tmp/m2p-site/build/check-report.md`: 9개 검사 모두 오류 0, 경고 0. `--sections` 생략 시 섹션 카드가 덮는 원문 파일을 검사한다.
- `python3 -m unittest discover -s redesign/tools/tests -v`: 2개 통과. 별도 임시 카드의 comparison.tex 227행 섹션 참조로 대상 자손을 직접 사용, 조상의 사용, 섹션 직접 사용은 통과하고, 해당 사용을 제거하면 경고가 실제로 생기는지 확인했다. export 시험은 별도의 임시 root에서 누락과 변조된 `.mmd`를 거부하는지 확인한다.
- `build.py --root /tmp/m2p-site --out /tmp/m2p-site/site`: 263개 HTML, 카드 244장. `Struct`에서 244장 전부 정확히 한 번 배정되고 미배정 0. `main:theorem`의 부모는 `model:section`, `reduction:section` 둘 다이며 주정리 묶음에 한 번 센다(자손 포함 5장). 생성된 카드 쪽에는 두 상위 링크가 있다. 지도 원문은 12개(전체 1, 상세 11).
- HTML 정적 검사: 263쪽에서 내부 링크 13,549개를 파일과 앵커에 대조해 깨진 링크 0. 한 파일 export는 263쪽, 약 4.67 MiB이며 상대 링크 잔여 0; 해시와 용어 앵커도 정적 검사에서 누락 0. 이는 클릭·레이아웃의 브라우저 검증이 아니다.
- 기존 `build/artifact/maps`의 12개 `.mmd`는 사본의 현재 카드에서 계산한 지도 원문과 전부 일치하고 각각 SVG가 있었다. 이 조건에서 기존 SVG를 복사해 export했고 성공했다. SVG 내용의 출처나 시각적 정확성은 `.mmd` 비교로 증명되지 않는다.

## 수정

- export가 다른 root의 SVG를 조용히 가져오는 일을 없앴다. 같은 root의 `.mmd`와 SVG를 요구하고, `.mmd`를 현재 카드로 다시 계산한 지도와 비교해 누락·불일치 시 중단한다. 이전 결과 파일을 새 결과로 오인하지 않도록 종료 코드도 실패다. 보관된 `.mmd`가 SVG 생성 시의 실제 입력이라는 전제는 남는다.
- `render_maps.py`가 시스템 Chromium과 런타임 Playwright 경로를 찾도록 했고, 임시 폴더에서 전부 그린 뒤 교체하므로 렌더 실패 시 기존 지도는 유지한다.
- 실행 순서, 의존성, root 격리, 지도 freshness 검사, `provides` 한계를 README에 추가했다. `provides`는 자유 산문에 축약 ID와 다른 설명이 섞여 있으므로 정밀한 양방향 대칭 검사를 가장하지 않는다. `\\ref` 없는 의존과 양쪽 기록의 일치는 사람의 검토가 필요하다.

## 브라우저와 남은 한계

Playwright와 `/usr/bin/chromium`을 실제로 실행해 보았다. `render_maps.py --root /tmp/m2p-site --mermaid /tmp/m2p-mermaid.min.js`는 `--no-sandbox`로 Chromium을 시작했으나 `socket() failed: Operation not permitted` 및 `Target page, context or browser has been closed`로 실패했다. 공유 브라우저의 `file:` 접근도 URL 정책에 의해 거부되었다. 따라서 **새 SVG 렌더링, MathJax 수식 오류 수, 휴대폰 폭 overflow, 지도 클릭과 export 라우팅의 실제 브라우저 동작은 미검증**이다. 이 환경에서 해당 차단을 우회하지 않았다. 정적 링크 통과를 브라우저 통과로 읽지 않는다.

## 최종 재생성

최종 카드가 안정된 뒤 저장소 루트에서 다음을 실행한다.

```sh
python3 redesign/tools/check.py
python3 redesign/tools/build.py
python3 redesign/tools/export_artifact.py
```

마지막 명령은 현재 카드에 대해 기존 12개 지도 입력이 일치하는지 다시 검사한다. 불일치하거나 SVG가 없으면 Playwright·Chromium을 쓸 수 있는 환경에서 먼저 `python3 redesign/tools/render_maps.py --mermaid /path/to/mermaid.min.js`를 실행하고 export한다. Mermaid를 생략하면 환경변수·vendor·npm 순서로 찾는다. 그 뒤 실제 브라우저에서 전체 수식, 지도 및 링크, 모바일 폭을 확인해야 한다. 본 보고서는 게시나 사용자 승인이 아니다.
