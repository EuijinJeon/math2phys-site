# L4 기존 HTML 재료 조사 — 2026-11-13

## 결론

`mezard-parisi-diluted/doc/`의 생성 HTML은 §6·§7에서 원문, 한국어 번역, 물리 해석과 항별 표를 실제로 제공한다. 별도 원본 저장소가 없어도 이를 보존하고 시범 편입하는 작업을 시작할 수 있다. 다만 생성 결과이지 편집 가능한 원본이 아니며, 문장 ID가 같다고 내용까지 같지는 않다. 원문 판본과 분할 차이를 먼저 대조해야 한다. 이 조사는 §6·§7만 검사했으며 나머지 절의 완전성을 보증하지 않는다.

## 구조와 재료

- 파일: `doc/06-perturbations-and-identities-on-prescrib.html`, `doc/07-decorrelation-on-prescribed-trees.html`. MkDocs Material 생성물. 본문은 `article` 내에 있고 문단은 `h4` 텍스트 `§6.1 ¶2` 등으로 시작한다. 앞에 별도 문단 앵커 `a#s6-1-p2`가 있다. 다음 문단 `h4` 또는 상위 섹션 제목 전까지를 맥락으로 보되, 문단 경계 밖의 소절 소개와 요약도 별도 보존해야 한다.
- 각 문단의 구획 표지는 `p > strong`의 정확한 텍스트 `원문`, `번역`, `물리 해석`. 원문 문장은 `p > a[id]`의 `s6-1-p2-s5` 같은 앵커와 `strong`의 `s5`; 번역 문장은 같은 구획 내 `p > strong`의 `s5`로 표시되나 자체 문장 앵커는 없다. 해석은 주로 `ul > li`의 `strong` 범위(예: `s1–s4`, `s1, s4`, 수식 번호 혼합)로 문장 여러 개에 걸친다. 범위의 의미를 잃지 말고 구획 단위로도 저장한다.
- `span.arithmatex`의 `\(...\)`·디스플레이 수식, 링크와 `a` 앵커, `details > summary`, `table`, 목록, 이미지 및 캡션이 존재한다. 원문 문장이 수식 블록으로 끊어질 수 있으므로 `p` 하나를 완결된 원문으로 가정하면 안 된다. 상대 링크와 이미지 경로는 원본 파일 기준으로 재해석해야 한다.
- 단순 정적 문자열 계수: §6은 문단 제목 36개, `원문`/`번역`/`물리 해석` 각각 36개, 페이지 전체 `table` 29개와 `details` 49개; §7은 문단 제목 32개, 각 표지 32/33/32개, 페이지 전체 표 39개와 details 32개. 표·details에는 문단 밖 요소도 포함되므로 이 수는 연결 가능한 항별 표의 수가 아니다. 추가 `번역` 표지는 일대일 대응을 가정하지 말라는 사례다.
- `redesign/source/NOTICE.md`는 `source/`의 수정되지 않은 논문 tex/bib 출처와 Apache License 2.0을 명시한다. 이것이 사이트의 한국어 2차 자료에도 같은 권한을 부여한다고 추정해서는 안 된다. 사이트 HTML의 저작권/재사용 조건은 이 조사에서 확인하지 않았다.

## ID와 내용 대조

`sentences.json` 필드: `id`, `section`(소절 포함), `para`, `idx`, `file`, `lines`(포함 양끝), `text`(TeX), `node`, `role`. HTML 앵커 `s6-1-p2-s5`를 기계적으로 `§6.1 ¶2 s5`로 바꿀 수 있다. 해당 규칙으로 HTML 원문 앵커를 세면 §6 186개 중 JSON ID 교집합 167개, HTML에만 19개, JSON에만 0개; §7 204개 중 교집합 173개, HTML에만 31개, JSON에만 0개다. 숫자는 ID 문자열의 집합 비교일 뿐 내용 일치율이 아니다.

- 일치 사례: `s6-p1-s1` ↔ `§6 ¶1 s1`, 둘 다 “Throughout this section the interaction and field are bounded …”로 시작한다. `s6-p1-s4` ↔ `§6 ¶1 s4`도 고정 매개변수의 기댓값 문장이다.
- 명백한 불일치: HTML `s6-1-p2-s5`는 “Enumerate these types by …”로 시작하지만 같은 JSON ID는 “Independently for each type, put …”로 시작한다. HTML의 그 문장은 `s6-1-p2-s6`이다. HTML `s7-1-p2-s2`는 “Additional ordering restrictions …”이나 JSON의 같은 ID는 “These are unnormalized averages …”이며 이는 HTML `s7-1-p2-s3`이다. 수식 및 원문 누락/분할 등 원인은 별도 분석 필요하다. 텍스트 정규화 유사도가 낮은 쌍은 수식·참조 렌더링 차이만으로도 생기므로 자동 판정 근거로 쓰지 않는다.
- `build.py`의 `source_html(c)`(약 506행)는 카드 `source` 범위의 원본 tex 줄을 이스케이프하여 `details.src > pre.tex`로 보여준다. `card_page`가 이를 호출한다. 현재 문장 ID나 번역을 읽어 표시하는 구현은 이 경로에 없다. 줄 범위가 겹치는 문장이나 여러 카드에 걸친 문장은 단순 1:1 연결을 전제하지 말 것.

## 가역적인 편입 제안

1. 원 HTML을 수정하지 않고 입력 파일 경로와 해시를 기록하여 별도 생성 데이터로 추출한다. 문단 키, 원 앵커, 원문·번역·해석의 원래 HTML 조각, 수식/표/부가 설명, 원본 URL·상대 링크 기준, 추출 버전을 보존한다. 구획 구분이 불명확하거나 라벨이 중복된 경우 통째로 보관하고 검토 대상으로 표시한다.
2. 문장 앵커의 변환은 후보 ID로만 취급한다. 원문과 JSON 텍스트를 TeX·HTML 수식 및 참조를 고려해 대조하고, 불일치·누락·1대다를 별도 매핑 파일에 기록한다. 예외를 수동 확인하기 전에는 번역을 해당 JSON ID의 확정 번역으로 붙이지 않는다. 맵은 입력과 별도 저장해 재생성·되돌리기가 가능해야 한다.
3. 카드 `source`의 파일과 줄 범위가 JSON 문장 `lines`와 겹치는 관계로 후보 문장을 찾고, 검증된 매핑을 통해 번역을 잇는다. 물리 해석·표는 원래 문단과 문장 범위를 유지하며 공유 연결한다. 출처 앵커와 원본 맥락 링크를 표시하고, 미검증·미대응은 숨기거나 추측 연결하지 않는다. 원문 텍스트는 기존 tex 및 JSON을 기준으로 유지한다.
4. §6·§7 소규모 시범에서 수식, 참조, 상대 이미지 링크, 범위형 해석, 표, 중복 제목과 문장 불일치를 눈으로 확인하고, 문장/번역 누락과 다중 매핑을 보고한다. 이후 전 절로 확장한다. 기존 사이트 번역·해석 자체의 수학적 정확성이나 최신 원문과의 일치는 이 조사에서 판정하지 않았다.

## 범위 추정

§6·§7에는 HTML 원문 앵커 390개, 문단 68개가 있어 기계 추출 시범은 현실적이다. 그러나 ID 교집합에도 어긋남이 있으므로 전체 890개 JSON 문장의 무인 결합은 안전한 추정이 아니다. 구현 규모는 구획 추출·보존과 렌더링 연결보다 불일치의 수동 판정, 수식/표/링크 QA가 좌우한다. 나머지 절을 동일하게 계수하고 대조하기 전에는 전체 인시를 확정하기 어렵다. 사용자에게 새 원본을 우선 요청할 필요는 없지만, 원본 저장소가 나중에 제공되면 버전과 편집 가능성을 대조할 가치가 있다.
