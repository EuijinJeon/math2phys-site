# 어려운 내용을 읽을 수 있게 다시 짓는 방법 — 작업 프롬프트

새 Claude Code 세션에 그대로 넘기는 작업 지시문이다. 대상은 특정 논문이 아니라 일반적인 "엄밀하고 어려운 원문"이다.
Mézard–Parisi 논문 시범 작업(`redesign/`)에서 실제로 겪은 것을 바탕으로 썼다. 근거가 되는 논의는 `notes/readability-lessons.md`, 설계는 `notes/redesign.md`, 실제 형식과 도구는 `redesign/SCHEMA.md`와 `redesign/tools/`에 있다. 이 문서만 읽어도 작업을 시작할 수 있게 썼고, 나머지는 예시로 참고하면 된다.

---

## 0. 시작할 때 채울 것

작업을 시작하기 전에 아래 넷을 사용자에게서 받거나 확인한다. 나머지는 묻지 말고 이 문서의 기본값을 따른다.

| 항목 | 내용 | 왜 필요한가 |
|---|---|---|
| 원문 | 고치지 않을 원본의 위치(.tex, 규격 문서, 코드 등) | 모든 주장이 여기에 닿아야 한다 |
| 독자 | 누가 읽는가, 무엇을 이미 아는가(바닥) | 같은 내용도 독자에 따라 최적 서술이 다르다 |
| 목적 | 원문을 옆에 두고 따라 읽는 동반 자료인가, 원문 없이 닫혀 있는 자료인가 | 뼈대가 달라진다. 아래 방법은 후자를 위한 것이다 |
| 기존 자료 | 이 원문에 대해 이미 만들어 둔 노트·해석이 있는가 | 참고는 하되 근거로 쓰지 않는다(5.2) |

## 1. 무엇을 만드는가

### 1.1 정의

Readability는 글의 속성이 아니라 (문서, 독자, 목적)의 속성이다. 독자마다 최적의 글이 다르므로, 누구에게나 읽히는 것은 한 편의 글이 아니라 **구조**다. 문서는 주장들의 의존 그래프이고, 독자는 자기 배경에 맞는 깊이에서 자른 **단면**을 읽는다.

원문의 순서는 검증에 맞춰져 있다(정의가 사용보다 먼저, 보조정리가 정리보다 먼저). 이해에 맞는 순서는 다르다(목표가 수단보다 먼저). 그래서 뼈대를 원문 순서가 아니라 의존 그래프로 잡는다. 원문은 맨 아래 근거층으로 남는다.

### 1.2 구조가 지켜야 할 것

| 조건 | 뜻 |
|---|---|
| 건전성 | 어떤 단면의 어떤 문장도 원문이 지지하는 것보다 많이 말하지 않는다 |
| 닫힘 | 각 단면에 쓰인 용어·기호·참조가 그 단면이나 용어집에서 해결된다 |
| 정초 | 모든 주장이 원문의 구체적 범위에 닿는다 |
| 포함 | 원문의 모든 논증이 어떤 단위에 들어 있다. 빠진 것이 없다 |
| 인터페이스 충분성 | 단위의 진술만 알면 그것을 쓰는 곳을 모두 따라갈 수 있다 |
| 역할 명시 | 각 단위가 무엇을 받아 무엇을 내놓는지가 본문보다 먼저 나온다 |

건전성이 나머지보다 우선한다. 원칙은 한 줄이다: **세부는 잃어도 되지만 참은 잃으면 안 된다.**

### 1.3 축약의 네 유형

축약한 문장은 아래 넷 중 하나여야 하고, 어느 것인지 표시한다.

| 유형 | 내용 | 표시할 것 |
|---|---|---|
| 같음(exact) | 같은 내용의 다른 표기 | 없음 |
| 약화(weakening) | 덜 말하지만 정확함 | 없음 |
| 블랙박스(blackbox) | 진술은 정확하고 근거만 숨김 | 근거가 있는 곳 |
| 근사(approximation) | 정해진 범위 안에서만 맞음 | 범위와 어긋나는 정도. 필수 |
| 직관(intuition) | 논증에 쓰이지 않는 그림 | 논증에 쓰이지 않는다는 표시 |

"어떤 축약이 허용되는가"(위 표)와 "허용된 것 중 무엇이 좋은가"(독자, 목적)는 다른 질문이다. 앞의 것은 통과와 실패로 판정하고, 뒤의 것은 그 뒤에 비교한다.

## 2. 산출물

레포에 아래를 둔다. 이름은 바꿔도 되지만 역할은 유지한다.

| 산출물 | 내용 |
|---|---|
| 원문 사본 | 고치지 않는다. 출처와 라이선스를 적는다 |
| 형식 규약 | 아래 모든 것의 형식. 작성자와 도구가 이 문서 하나로 맞물린다. **작성을 맡기기 전에 먼저 쓴다** |
| 노드 카드 | 주장 하나에 파일 하나(2.1) |
| 규칙 표 | 독자판이 근거 없이 쓰는 명제들과, 각각이 원문의 어느 주장인지(2.2) |
| 단면 문서 | L0 한 문단, L1 한 쪽(2.3) |
| 용어집 | 용어마다 뜻, 역할, 정의 위치, 쓰지 않는 뜻(2.4) |
| 의존 지도 | 주장 단위의 그래프. 첫 화면 |
| 로드맵 | 단계, 결정 기록, 날짜별 진행 기록 |
| 인계 문서 | 새 세션이 대화 기록 없이 이어받기 위한 문서(7.4) |

### 2.1 노드 카드

모든 내용(정의, 가정, 주장, 논증의 단계, 약속)을 고정된 칸을 가진 카드로 쓴다.

| 칸 | 내용 |
|---|---|
| ID | 원문에 이름표가 있으면 그것. 없으면 작성자가 붙이되 구별되는 접두어를 쓴다 |
| 받는 것 | 이 주장이 기대는 다른 노드. 범위가 넓은 약속("이 절 내내 …")도 노드로 만들어 여기에 넣는다 |
| 내놓는 것 | 누가 무엇에 쓰는지 한 줄 |
| 정확한 진술 | 받는 것과 용어집만으로 읽혀야 한다. 약화는 되지만 틀리면 안 된다 |
| 독자판 진술 | 독자의 언어로 쓴 대응 진술. 대응이 없으면 비운다 |
| 차이 | 독자판이 정확한 진술과 어긋나는 곳, 유효 범위 |
| 유형 | 1.3의 다섯 중 하나 |
| 펼침 | 하위 단계들. 각각이 다시 카드 |
| 원문 범위 | 근거가 되는 파일과 행 |
| 승인 | 작성자는 "제안"으로 둔다. "확정"은 사용자만 붙인다 |

카드의 윗부분(받는 것부터 유형까지)이 인터페이스다. 다른 카드는 인터페이스만 참조한다. 부모 카드의 논증 요약은 자식들의 **진술**만으로 완결되어야 하고, 자식의 본문에만 있는 사실에 기대면 안 된다.

### 2.2 두 판과 규칙 표

상세도와 언어는 다른 축이다. "얼마나 자세히"는 펼침으로 조절하고, "어떤 언어로"는 판을 나눈다.

- **독자판**: 독자의 분야가 쓰는 언어로 된 독립된 서술. 규칙 목록과, 규칙만 써서 결과에 이르는 짧은 유도로 이루어진다.
- **원문판**: 원문의 언어로 된 계층적 논증.
- **규칙 표**: 독자판의 규칙 하나하나가 원문의 어느 주장에 대응하는지, 어디서 어긋나는지.

규칙에는 독자가 당연하게 여기는 것뿐 아니라, 당연하지 않더라도 **근거가 무겁고 진술이 쓰기 좋은** 것을 넣어도 된다. 그런 행에는 "이것은 독자 분야의 가정이 아니라 원문이 증명한 보조 결과"라고 적는다.

원문과 독자의 언어가 같으면 판을 나눌 필요가 없다. 그때는 규칙 표가 "근거 없이 받아들이는 것의 목록"이 된다.

### 2.3 단면

| 단면 | 분량 | 내용 |
|---|---|---|
| L0 | 한 문단 | 결과와 의미 |
| L1 | 한 쪽 | 전체 논증을 일곱 수 안팎으로. 수마다 무엇을 하는가, 어떤 규칙을 쓰는가, 근거 노드 |
| L2 | 수 쪽 | 규칙 목록과 유도 |
| L3 | 전체 골격 | 모든 주장의 진술과 최상위 단계 |
| L4 | 전체 | 원문 문장 |

각 단면은 첫 줄에 전제하는 배경(바닥)을 선언한다. 독자는 L0에서 들어와 필요한 곳만 펼친다. 일부만 펼친 상태도 참이고 읽혀야 한다.

재배열은 위층(L0–L2)에서 자유롭고, L3에서는 의존 순서를 지키는 한에서만, L4에서는 하지 않는다.

### 2.4 용어집

**용어집은 마지막이 아니라 처음에 만든다.** 시범 작업에서는 나중에 만들었고, 그 사이에 같은 낱말이 여러 뜻으로 쓰이고 정의 없는 용어가 윗단면에 들어갔다.

항목마다 다음을 적는다.

- **뜻**: 이 문서에서의 정확한 정의.
- **역할**: 논증에서 무엇에 쓰이는가, 누가 받아 쓰는가. 독자가 가장 필요로 하는 칸이다.
- **정의 위치**: 원문의 노드나 행.
- **독자 분야의 대응**: 독자가 아는 개념과의 관계와 그 유형(1.3).
- **쓰지 않는 뜻**: 이 낱말로 가리키지 않는 것. 과하게 읽히기 쉬운 용어에는 반드시 적는다.

## 3. 절차

### 3.1 준비

1. 원문을 복사하고 출처를 적는다.
2. 원문에서 기계적으로 뽑을 수 있는 것을 뽑는다: 이름 붙은 단위, 이름표, 상호 참조, 문장 번호. 이것이 의존 그래프의 첫 판이고 이후 검사의 기준이다.
3. 형식 규약을 쓴다. 카드 칸, ID 규칙, 검사 목록까지.
4. 로드맵을 쓰고 커밋한다.

원문이 명시적 "정의" 단위를 갖지 않을 수 있다(시범 논문에는 하나도 없었다). 정의가 본문 서술에 묻혀 있으면 기계로 뽑히지 않으므로 작성 단계에서 손으로 묶어야 한다.

### 3.2 시범을 먼저 한다

전체를 짓기 전에 가장 싸게 실패할 수 있는 두 가지를 먼저 만든다.

1. **전체의 L0, L1, 규칙 표.** 독자판이 닫히는지를 본다.
2. **한 절의 카드 전부.** 카드 형식이 실제 논증을 빠짐없이 담는지를 본다.

판정 기준은 시작 전에 로드맵에 적는다. 예: 규칙이 열 개 안팎으로 닫히는가, L1의 각 수가 규칙만으로 이어지는가, 그 절의 모든 논증이 잎 카드에 들어가는가, 검토에서 구조를 흔드는 오류가 나오는가.

### 3.3 작성

- **L1은 원문 저자의 요약에 고정한다.** 대부분의 원문에는 저자가 쓴 개요가 있다. 그것을 뼈대로 삼으면 작성자가 구조를 지어낼 여지가 줄어든다.
- **위에서 아래로 쓴다.** L0, L1, 규칙 표, 그다음 카드.
- 작성자에게는 원문을 **전부** 읽게 한다. 요약이나 기존 노트만 보고 쓰게 하지 않는다.
- 작성자가 확신이 없는 곳은 진술을 약화하고 표시를 남기게 한다. 표시는 검토에서 해소한다.

### 3.4 기계 검사

통과와 실패로 판정한다. 최소한 다음을 둔다.

| 검사 | 통과 조건 |
|---|---|
| 형식 | 모든 카드의 칸이 규약대로다 |
| 정초 | 모든 카드가 실재하는 원문 범위를 가리킨다 |
| 포함 | 대상 범위의 모든 논증 줄이 어떤 잎 카드에 든다 |
| 의존 | 카드의 원문 범위에 나오는 참조가 "받는 것"으로 설명된다 |
| 연결 | 모든 가리킴이 실재하는 대상을 가리킨다 |
| 순환 | 의존에 순환이 없다 |
| 사전 | 규칙과 독자판 진술마다 대응 노드, 차이, 유형이 있다 |
| 단면 | L1의 모든 수가 규칙이나 노드를 가리킨다 |
| 용어 | 모든 용어 가리킴이 용어집에 있고, 항목마다 뜻·역할·정의 위치가 있다 |

검사에 관한 규칙 셋.

1. **가리킴의 종류마다 검사가 있어야 한다.** 시범 작업에서 문서 전체가 외부의 표를 번호로 가리켰는데 그 표가 문서 안에 없었다. 검사가 노드와 규칙 번호만 보았기 때문에 아무도 알아채지 못했다.
2. **검사가 실패하면 내용을 고친다.** 검사 규칙이 설계와 어긋나서 규칙 쪽을 고쳐야 할 때는 그렇게 하되, 무엇을 왜 완화했는지 로드맵에 적고 사용자에게 알린다.
3. **기계 검사는 형식과 포함만 본다.** 통과했다고 내용이 맞다는 뜻이 아니다.

### 3.5 독립 검토

건전성, 과장, 가정 누락, 인터페이스 누수는 기계가 잡지 못한다. 시범 작업에서 나온 지적 28건 전부가 독립 검토에서 나왔다.

- 검토자는 작성에 관여하지 않은 에이전트이고, 작성자와 다른 모델을 쓴다.
- 임무는 개선이 아니라 **틀린 곳과 과장된 곳을 찾는 것**이다.
- 모든 지적에 원문의 파일과 행을 붙이게 한다.
- 지적을 분류하게 한다: 틀림 / 과장 / 구멍(자식이 부모를 함의하지 않음) / 누수(본문에만 있는 사실에 기댐) / 유형 오류 / 표기.
- 검토자가 읽지 않은 범위를 밝히게 한다.
- 인터페이스 시험을 시킨다: 부모 카드와 자식들의 **진술만** 보고 논증 요약을 재구성할 수 있는가.
- 작성자가 스스로 놀랍다고 보고한 주장은 따로 검증시킨다. 사용자에게 전달될 가능성이 높기 때문이다.

### 3.6 수정

- 수정자는 검토자의 지적을 **원문과 다시 대조한 뒤** 반영한다. 검토자도 틀린다(시범에서 행 번호 네 곳, 제안 문구 세 개).
- 지적마다 맞음 / 일부 맞음 / 틀림과 조치를 표로 남긴다.
- 같은 문제는 나타나는 모든 곳에서 고친다.
- 수정 뒤 기계 검사를 다시 돌린다.
- 여유가 있으면 수정본을 다시 독립 검토한다. 하지 않았으면 하지 않았다고 적는다.

### 3.7 확장과 평가

시범이 통과하면 나머지를 절 단위로 같은 순서(작성 → 검사 → 검토 → 수정)로 진행한다. 새 용어가 나오면 용어집에 먼저 더한다.

평가는 선호 비교 전에 측정으로 한다. 단면만 떼어 본문을 볼 수 없는 독자(모의 독자)에게 주고 하류 질문을 풀게 한다.

## 4. 반복해서 나온 실패와 대처

시범 작업에서 실제로 일어난 것들이다.

### 4.1 익숙한 이름을 붙일 때 과장이 생긴다

과장 지적의 대부분은 원문의 대상에 독자 분야의 익숙한 이름을 붙이면서 생겼다. 이름은 원문이 증명하지 않은 동일시를 함께 실어 온다.

- 원문이 증명하지 않는 동일시를 담은 이름은 규칙 문장과 독자판 진술에 쓰지 않는다. 용어집의 "독자 분야의 대응" 칸에 직관으로만 적는다.
- 원문이 선행 연구로만 언급한 것을 "원문의 결과가 그것과 같다"로 옮기지 않는다.
- 이름이 독자에게 주던 정보가 있었다면 그 정보를 **진술로** 적는다. 예: 어떤 이름이 "이것만 있으면 뒤가 다 따라 나온다"는 무게를 전달했다면, 이름을 빼고 "이것과 무엇만으로 무엇이 따라 나온다, 무엇은 따라 나오지 않는다"를 원문 근거와 함께 쓴다. 그렇게 쓰고 보면 이름이 주던 인상이 절반만 맞았다는 것이 드러나기도 한다.

### 4.2 생성물은 원문이 아니다

이전 작업에서 만든 노트, 해석표, 요약은 원문이 아니다. 참고는 하되 근거로 쓰지 않고, 새 구조에 그대로 들여오지 않는다. 쓸 만한 내용은 원문과 대조해 새 형식으로 다시 쓴다. 기존 자료가 "확정"이라고 표시한 것도 원문이 지지하는지 다시 본다(시범에서 확정 표시가 붙은 항목 하나가 원문이 증명하지 않는 동일시였다).

### 4.3 한 낱말은 한 뜻

독자 분야의 일상 용어일수록 여러 뜻으로 미끄러진다. 시범에서는 "상태"가 세 가지를 가리켰다. 용어집에서 뜻을 하나로 정하고, 다른 것을 가리킬 때는 풀어 쓴다. 형식 규약의 열 이름 같은 곳에서도 그 낱말을 다른 뜻으로 쓰지 않는다.

### 4.4 건전성을 지키면 윗단면이 부푼다

검토 지적을 반영하면 L0과 L1에 조건과 단서가 쌓여 길어진다(시범에서 L0이 1.6배). 풀어 쓰지 말고 **가리킨다.** "규칙 1의 가정 아래"는 덜 말할 뿐 틀리지 않으므로 적법한 약화다. 빠진 세부는 "정확한 진술" 절이나 해당 카드로 옮겨 잃지 않는다.

### 4.5 대응이 없는 곳에 억지로 해석을 붙이지 않는다

원문의 순수 기술 단계에는 독자 분야의 대응이 없을 수 있다. 독자판 진술을 비우고 블랙박스로 둔다. 반대로 깔끔한 대응이 있는데 비워 둔 곳도 검토에서 찾게 한다.

### 4.6 차이 칸이 가장 값진 칸이다

독자가 이미 아는 그림과 원문이 실제로 증명한 것 사이의 차이(어떤 평균에서만, 어떤 극한 순서에서만, 어떤 가정 아래에서만, 어떤 대상에 대해서만)가 이 작업이 독자에게 주는 가장 큰 정보다. 차이를 적을 때는 원문의 행을 붙인다.

### 4.7 앞을 가리키는 참조는 의존이 아니다

"이 결과는 뒤의 절에서 쓴다"는 예고다. 받는 것에 넣으면 방향이 뒤집힌다.

### 4.8 가정의 역할을 나눠 적는다

원문의 가정들은 논증의 서로 다른 부분에 쓰인다. 어느 가정이 어디에 쓰이는지 규칙 표에 적는다. "이 가정은 여기에만 쓰인다"는 문장은 검토에서 틀리기 쉬우므로 반드시 원문의 사용처를 전부 확인한다. 원문이 주장하지 않은 일반화를 암시하는 표현도 피한다.

## 5. 사용자에게 보고할 때

- 하위 에이전트의 보고를 검증된 사실처럼 전하지 않는다. 누가 확인했고 누가 확인하지 않았는지를 구분한다.
- 사용자의 기존 이해와 어긋나는 발견은 따로 모아 먼저 보여 준다. 그리고 그 주장이 독립 검토를 거쳤는지를 함께 말한다.
- 앞서 전달한 것이 나중에 틀린 것으로 드러나면 다음 보고에서 바로잡는다.
- 검사 규칙을 완화했거나, 하지 않은 검증이 있으면 묻기 전에 말한다.
- 사용자만 정할 수 있는 것(규칙의 확정, 용어의 이름, 다음 단계로 갈지)은 목록으로 모아 한 번에 묻는다. 작성물의 "확정"은 사용자만 붙인다.

## 6. 원문의 종류가 다를 때

위 방법은 증명이 있는 수학 논문을 물리학자에게 옮기는 작업에서 나왔다. 다른 원문에는 아래처럼 대응시킨다.

| 이 문서의 말 | 규격·법률 문서 | 코드베이스 | 실험 논문 |
|---|---|---|---|
| 주장 노드 | 조항, 요구사항 | 모듈, 함수의 계약 | 결과, 방법의 단계 |
| 논증의 단계 | 조항의 근거와 예외 | 구현 | 분석 절차 |
| 받는 것 | 인용하는 다른 조항, 정의 | 의존하는 모듈 | 전제한 측정과 가정 |
| 독자판 | 실무자가 따르는 절차 | 사용자가 보는 동작 | 주장의 평이한 진술 |
| 차이 | 절차가 조문을 단순화한 곳 | 문서화된 동작과 실제의 차이 | 주장이 데이터를 넘어서는 곳 |
| 블랙박스 | 세부 시행 규정 | 내부 구현 | 장비 세부 |

어떤 원문이든 그대로인 것: 원문을 고치지 않는다, 모든 주장이 원문 범위에 닿는다, 축약의 유형을 표시한다, 용어집을 먼저 만든다, 기계 검사와 독립 검토를 둘 다 거친다.

## 7. 작업 운영

### 7.1 역할 나누기

주 세션은 조율만 한다. 형식 규약을 정하고, 일을 나누고, 결과를 검사하고 통합하고 커밋한다. 원문을 정독하는 일과 긴 글을 쓰는 일은 하위 에이전트에 맡긴다. 이렇게 하면 주 세션에는 보고서만 쌓여 오래 버틴다.

| 일 | 맡길 곳 |
|---|---|
| 추출·검사·화면 생성 도구 | 코딩에 충분한 가벼운 모델 |
| 원문을 정독해야 하는 작성 | 가장 강한 모델 |
| 독립 검토 | 작성자와 다른 모델 |
| 수정 | 강한 모델. 원문 재대조를 명시 |

### 7.2 에이전트에게 줄 지시에 넣을 것

- 목적과 이 문서의 1.2, 1.3. 규칙만 주지 말고 이유를 준다.
- 읽을 것의 정확한 경로. 형식 규약, 원문, 참고만 할 기존 자료.
- 쓸 수 있는 디렉터리와 건드리면 안 되는 디렉터리. 병렬 작성자끼리 겹치지 않게 한다.
- git 명령 금지. 커밋과 푸시는 주 세션이 한다.
- 끝난 뒤 스스로 할 점검(가리킴이 실재하는가, 범위가 빠짐없이 덮였는가).
- 보고에 담을 것: 무엇을 만들었나, 약화하거나 표시를 남긴 곳, 기존 자료와 원문이 어긋난 곳, 형식 규약에서 애매했던 곳.

### 7.3 병렬과 한도

서로 다른 디렉터리에 쓰는 작업은 병렬로 돌린다. 한꺼번에 여럿을 돌리면 사용 한도에 걸릴 수 있으므로 두세 개씩 한다. 한도로 멈춘 에이전트는 새로 띄우지 말고 이어서 하게 한다. 진행 중에도 주기적으로 중간 스냅샷을 커밋한다.

### 7.4 상태는 대화가 아니라 레포에 둔다

- 로드맵에 단계, 결정과 이유, 날짜별 진행, 하지 않은 것을 적는다. 진행할 때마다 갱신한다.
- 인계 문서에 목적, 원칙, 작업 방식, 도구 명령, 현재 위치, 사용자가 정한 것, 확인을 기다리는 것을 적는다. 새 세션이 이 파일만 읽고 이어받을 수 있어야 한다.
- 단계가 바뀌는 지점에서 인계 문서를 갱신하고, 그때 새 세션으로 넘어간다.

### 7.5 화면

읽는 사람이 실제로 펼쳐 보며 읽을 수 있는 화면을 만든다. 카드는 인터페이스가 먼저 보이고 하위 단계가 제자리에서 펼쳐지게 한다. 용어는 본문에서 뜻이 바로 보이고 용어집으로 이어지게 한다. 화면은 사람이 보기 전에 실제 브라우저에서 수식, 링크, 펼침, 좁은 폭을 확인한다.

## 8. 한계

- 모든 내용이 층으로 나뉘지는 않는다. 의존이 촘촘히 얽힌 부분은 어떤 순서로도 열어 둔 항목이 많다.
- 논증을 단계로 나누는 계산 절차는 없다. 판단이고, 그래서 제안과 확정을 나눈다.
- 독자판이 닫히지 않는 지점이 나올 수 있다. 그 지점은 이 원문에서 독자 분야식 축약이 존재하지 않는 곳이고, 그대로 기록한다.
- 독립 검토를 거쳐도 오류는 남는다. 시범 작업에서 검토자 스스로 읽지 않았다고 밝힌 범위가 있었고, 수정본의 재검토는 하지 못했다.
